Login (source auth — same OTP token har service me)

Portal ka koi apna auth nahi hai — /auth/* source-service se login lo, yahi token /portal/* pe bhi chalta hai. University (HEI source-account owner): apne source phone se login karo → GET /portal/me pe auto-bind hoga. Student: koi bhi 10-digit phone register/login karke POST /portal/participants se STUDENT bano.

My portal participant profile

Yahi endpoint participant banata/detá hai. University owner (HEI account) pe pehli baar auto-bind hota hai — alag registration nahi. Student ko pehle register karna padta hai, warna 404 STUDENT_NOT_REGISTERED.
Profile yahan aayega.

Register as a STUDENT participant

Sirf tab jab /portal/me ne 404 diya ho. University-account owner yahan 409 HEI_ACCOUNT_REGISTERED_AS_UNIVERSITY paayega (wo auto-bind hota hai, STUDENT nahi ban sakta).

Published problems (catalog)

Sirf wahi problems dikhti hain jo evaluation complete hone ke baad auto-publish hui hain, aur sirf wahi jo aapki participant kind dekh sakti hai — STUDENT ko sirf OPEN_TO_ALL; UNIVERSITY ko restricted bhi. Invisible problems yahan leak nahi hoti.

Problem statement (full)

Yehi wo statement hai jo portal dikhata hai — description + expectedOutcome + source/urgency/severity/location/domains/evidence + access rule. Statement evaluation complete hone ke baad hi milta hai.
Catalog me se koi problem kholo.

New submission (draft)

Problem pick karo → team (optional) + title/summary/github/links bharo → Create DRAFT. Draft bante hi neeche workbench me khul jayega jahan file upload karke Submit for review karoge. Har submit ek naya review round hai — RETURN hone par edit karke dubara submit kar sakte ho.
